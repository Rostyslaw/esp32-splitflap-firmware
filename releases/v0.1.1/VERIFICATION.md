## Розмір та розділи

- `esp32-splitflap-idf.bin`: **1 054 976 байтів**, разом із усіма ресурсами вебпанелі.
- Кожен із двох OTA-слотів: **2 031 616 байтів** (`0x1F0000`).
- Вільно в кожному слоті після цього образу: **976 640 байтів**, приблизно **48%**.
- `firmware.sfu`: **1 055 488 байтів**, включно з 512-байтовим підписаним заголовком.
- Bootloader: 21 136 байтів; partition table: 3 072; OTA data: 8 192.
- Flash: DIO, 40 MHz, **4 MB**; останній слот закінчується точно на `0x400000`.
- Application SHA-256: `d0441b04ee22997a80a623d6d6d317ac8df9fe72bf284150e110bd24493267c4`.
- Package SHA-256: `87eec8ecb8213af5f6513010ba413c99b8e843f837eff32d244b0b07aaad2752`.

CI size report: DIRAM статично зайнято 99 502 байти з 341 760; це не замір вільної heap під час HTTPS. Реальна heap показується API. Boot rollback увімкнено; hardware secure boot, flash encryption та eFuse anti-rollback не увімкнено. Основна консоль UART0 115200, додаткова — USB Serial/JTAG.

У Windows поточний Xtensa15 блокується Smart App Control; захист системи не змінювався. Частину host-тестів виконано локально дозволеним Zig0.13; остаточні всі результати вище походять з успішного Linux CI. Публікується саме його образ, а не незавершений локальний build.

## Межі перевірки

Плату не прошивали, порти пристрою не відкривали, двигуни не запускали. Фізичні Hall, струми/температура драйверів, точність позицій, справжній AP+STA, передавання OTA на ESP та rollback при втраті живлення ще потребують випробування на пристрої. Browser preview використовував модель API, а не ESP32.

Достовірно зі старих файлів відновлено GPIO5/6 та групи PCF0/4. GPIO двох інших Hall і фізичний порядок нового монтажу не встановлено. Старий `main.cpp` після завершення роботи має той самий SHA-256, що до неї: `0ba37ab9a17378a3a76ca3ae8d43feaf6abf2445e6b43af649224c6e52bd2e86`.

## Повторення

Усі точні Linux-команди тестів і складання містяться у `.github/workflows/build.yml`; повторний запуск доступний через GitHub Actions → Firmware checks → Run workflow. Для локального ESP-IDF використайте `idf.py set-target esp32s3`, `idf.py build`, `idf.py size`. `dependencies.lock` зберігає перевірені компоненти `espressif/cjson 1.7.19~2`, `espressif/mdns 1.14.0` та їхні хеші.
